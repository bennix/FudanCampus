**2026-09-29 执行优先级已修订：以 [照片空间形态修订计划](shape-first-revision-plan.md) 为准。暂停扩展生成器与工程细节；先纠正下梯后的方向、弧度和隆起。本文算法只保留为辅助工具。**

原始状态：方法与验收约定，计划轮只写文档，不改模型。后续执行记录见 [西出口生成器小样](road-rebuild-v1/README.md)：生成器已实现并通过代表性测试，局部模型仍未通过现场剖面与肩部形态验收。

## 1. 当前判断与起点

- 整体 v3 是受保护的整体基线；stage01-east.blend 保留上一轮东高台修改，作为提取现有对象、相机和比较的工作起点，不等于道路已经合格。
- stage02-east-path-repair.blend 及其试验图不作为验收基线。早期三维布尔试验产生大范围道路缺面；后续三角网格试验仍有出口局部形态异常，不能凭成功保存或重开宣布修复完成。
- 已确认的程序问题：原道路由许多独立分段实体拼接，支路直接叠加；随后又按草坡高度抬升部分路面顶点。这样的生成顺序缺少统一交叉口和平滑的道路纵断面约束。
- 黑斑可能同时涉及重叠面、拓扑和表面方向；不能只凭颜色将每一处归因于法线。铺装纹理的深色线条也不能直接当作真实裂缝，须用纯色材质和网格检查区分。
- 305 张索引沿用既有记录，本轮没有重新完成一次逐图复核。与下一次改动相关的照片必须重新打开确认。

## 2. 固定的生成方法

采用“有证据的路网 → 二维道路轮廓 → 有约束的三角网格 → 独立道路高程 → 匹配路边的地形 → 厚度、材质和导出”。这是本场景选定的工程方案，不声称适用于所有道路或复杂立交。

生成器只能读取路线数据和受保护场景，输出新文件；不得从上一轮损坏的三角面反复修补生成下一轮。

### 2.1 路网先行

建立节点和路段图：节点包括分叉、平台出口、台阶落点、草坪边直道接口、明确终点；路段保存中心线、宽度、高程控制和来源。

- 只有明确登记为同一节点、同一地面层的道路才能合并。平面靠近或投影相交不代表实际连通。
- 连续园路、踏石、楼梯、平台、地下坡道分开建模。踏石不能并成整条路，楼梯不能用坡面代替，地下未知范围不补齐。
- 中心线用于普通道路；花园节点、出口和不规则拓宽处允许照片约束的左右边界或局部轮廓优先。
- 每项观察分别标记 confirmed / inferred / unknown；存在、连接、朝向、宽度和高差分别记录可信度，不能用一个“已确认”覆盖整条路。
- 所有道路输入固定使用一个场地坐标系。现有东区注册偏移只在明确的坐标转换处应用一次；网页集成缩放不进入本地建模数据。

### 2.2 二维轮廓先解决连接

1. 平滑曲线必须经过核对后的控制点，并通过弦误差自适应采样。检查内弯半径与半路宽的关系，防止偏移边界翻折。
2. 等宽段由中心线偏移得到左右边界；变宽段按弧长连续变化；台阶端采用与踏步前缘完全一致的端线。
3. 在登记的交叉口范围内做二维多边形并集，得到一个外轮廓和明确的内部孔洞。交叉口圆角、拓宽程度是显式参数，不依赖分段实体互相覆盖。
4. 验证每个多边形有效、无自交、无重复边，并且其连接分量与路网一致。尖角和狭长草地岛单独报告，不自动填掉可能真实存在的花池或岛。
5. 与草坪、花池、采光顶、楼梯口保护范围发生冲突时停止该路段，不自动挪动受保护对象。

固定技术路线：独立 Python 环境用 Shapely / GEOS 做二维缓冲、交并差和有效性检查；Blender 负责生成、查看与保存三维模型。实施时先验证 Shapely 2.1.2、GEOS >= 3.10 的所需接口，再锁定实际环境与依赖；此次不安装依赖。若环境不满足，先解决环境，不临时退回三维布尔拼接。

### 2.3 轮廓通过后再三角化

- 对有效道路多边形使用约束 Delaunay 三角化，保留外边界和孔洞。普通无约束 Delaunay 不能作为替代。
- 平台接缝、坡度分区、材质分区作为显式约束边；先切成共享边界的面域，再进行三角化与顶点去重。
- 坡面按误差增加采样点并一致细分相邻三角形，禁止单侧细分产生 T 形接缝。三角化本身不保证高程精度或优良三角形质量，仍须检查。
- 顶点按统一精度去重，内部共享边只保留一份。禁止将重叠路面和草坡三角形一起输入后，仅用三角形中心点猜测铺装归属。
- 数值初值：坐标吸附精度 1e-5 模型米，中心线弦误差上限 0.01 模型米，坡面采样目标边长不大于 0.25 模型米；根据误差验证调整。它们是计算精度，不是现场测量精度。

### 2.4 高程由道路剖面决定

- 每段道路定义沿弧长的 z(s)，由端点、平台、台阶落点和可靠剖面关系约束；采用不引入过冲的插值。
- 分叉共享节点高度，在局部交叉口面片中连续过渡；不要对多条路线高度简单取最大值。
- 楼梯踏步和平台保持明确的高差断点；普通园路必须位置连续。坡度变化尽量平顺，但未知处不能为了顺滑擅自改变平台高度。
- 先画西出口与北出口的“平台—短梯—落地段—主路”纵断面，再生成三维表面。未有测量支撑的高度与坡长明确标为推定。
- 禁止使用“将道路抬到所有草坡之上”的逐顶点 max 操作，也禁止为了不穿模自动产生新土包。
- 如果现有平台标高、已知连接和合理剖面无法同时满足，输出冲突和备选假设；不要强行扭曲道路闭合。

### 2.5 地形服从已验证的道路边界

- 道路与地形各有明确面域。地形在道路足迹内开出占位，避免草地顶面与路面重叠；地形边界和道路边界共享平面采样点与对应高程。
- 肩部坡面从道路边缘过渡到原地形；宽度和高差是可审查参数。保持需要的路缘高差，避免道路悬空和草坡遮路。
- 只允许修改 EPATH 的局部过渡地形；主草坪、既有外围道路及其他地点对象保持原状。触及这些边界时先报告关系冲突。
- 地下楼梯洞口、采光顶基座和挡墙是地形的保护约束；不让自动坡面覆盖它们。

### 2.6 最后加厚和铺装

- 每个物理连续的路面分量形成共享顶点的连续表面。只沿真正的外轮廓、孔洞和明确构造分缝生成侧面；内部三角形不逐块挤出。
- 需要实体的部分在统一顶面通过后生成底面和侧壁，验证闭合及体积方向。与土体交接的构造厚度保持推定说明。
- 顶面 UV 使用统一的米制平面映射，支路与主路连续；明显坡道可另设局部坐标，但接缝必须位于指定分缝。
- 保留照片中存在的压纹铺装，调整纹理尺度之前先通过纯色几何验收。不能以消除所有铺装线条来掩盖几何问题，也不使用噪声或植被遮挡缺面。
- 路缘石、排水沟等只在证据支持时增加。

## 3. 数据和可重复生成约定

计划新增以下文件，名称为实施约定，尚未生成：

- road-network.json：节点、路段、连通关系、surface_layer、中心线/左右边界、宽度、z(s) 控制、照片来源、各项可信度和待核查问题。
- road-protection.json：保护对象 ID、哈希、草坪与洞口等禁止侵入边界，以及允许调整的区域。
- road-generation-config.json：精度、曲线和网格参数、算法版本、依赖版本；禁止散落于多个临时脚本。
- road_geometry.py：纯二维轮廓、路网与网格计算模块，不导入 bpy。
- build_roads_blender.py：读取结果生成 Blender 网格、元数据和统一 UV。
- validate_roads.py：计算验证与报告；失败退出，不覆盖已通过版本。
- road-generation-tests/：直段、急弯、T/Y 交叉口、变宽、带岛孔洞、相近但不连通、同层/异层交叉、坡道接平台、台阶接路等代表性小样例。

证据数据与算法分开维护。对象继续保留 EPATH / WPATH 等地点 ID；每个生成面域关联 segment_id / junction_id，合并网格不能丢失来源。输入与配置相同应输出相同的几何摘要。

## 4. 必须通过的验收

|检查|通过条件|失败处理|
|路网连通|实际道路分量和节点邻接与登记路网一致；每个要求连通的入口均可沿路面到达出口|定位具体节点，不用提高焊接距离强行连接|
|二维覆盖|三角形并集与目标道路面域在数值容差内一致；无重叠面积、漏面或被意外填平的孔洞|回到轮廓/三角化，不进入三维|
|网格接缝|共边坐标一致；无重复面、退化面、内部开放边、T 形接缝及翻转顶面；实体加厚后闭合|输出问题边和位置|
|高度衔接|普通道路节点高度一致；梯脚、梯顶、平台接边符合明确剖面；不出现未设计的竖直断面|回到高程约束，不抬整段地形|
|地形冲突|沿全路及边缘采样，无土面高于路面的穿出；无保护边界侵入；检查横断面|修局部地形边界，不扩大土包|
|保护与身份|非目标对象、主草坪和保护文件摘要不变；地点 ID 和证据来源完整|停止输出通过版本|
|视觉|全路纯色顶视、线框局部、出口低视角均无缺块/黑洞/交错碎片；材质版无新增遮挡|视觉不过关即失败，即使自动检查通过|
|交付|新检查点可重开；导出阶段 GLB 可重新导入并在目标网页查看|区分模型通过与导出失败，不发布失败资产|

计算验收使用固定配置里的数值容差；不会把厘米级建模误差误称为实景精度。纯色检查和纹理检查必须同时保留。

## 5. 分阶段实施与停止条件

1. **冻结基线和旧试验状态。** 记录整体 v3、stage01、原图及已有资产哈希；将 stage02 标为未通过试验。原文件保留，不以删除或覆盖代替回退。新工作不从 stage02 继承。
2. **只核对东路网与剖面。** 打开 4565、4568 及相邻反向照片，核对西出口；打开中层北出口、EPATH 分叉和草坪接口对应照片。绘制平面图和两条纵断面，明确保留哪些推定。必要时对比假设，不凭路线相邻认定同一对象。
3. **先验证生成器小样例。** 在空场景生成代表性道路，不带植被纹理。证明并集、孔洞、分叉、坡道、加厚和元数据保留均可重复通过。
4. **小范围试建西出口。** 仅处理西侧短梯落点至主路交叉口，保留 ETERR 和采光顶。输出同机位前后、纯色顶视、低视角、纵断面和 4568 并排图。相机未标定必须注明近似视角。
5. **再处理北出口与整条 EPATH。** 复用同一生成器；先完成全路平面连通，再逐段处理高程和肩部。不得只检查中间裁剪区域，要覆盖南北端、所有分叉和出口。
6. **扩展到 WPATH。** 使用同一算法但独立证据数据；连续园路、独立踏石、草坪边直道分别处理。不同花园不共用几何模板。
7. **恢复整体精修顺序。** 复核 ETERR 平台轮廓与楼梯关系 → ESKY/ERAMP 邻接 → WTERR 与 WPATH 接口 → 四处楼梯口分别定向 → WB1/WB2 与高台关系 → 广场/楼前台阶边界。缺证据的结构保留未知，不靠“不穿模”裁短对象。
8. **材质与植被。** 结构全部稳定后核对压纹铺装尺度、材质连续性、座椅比例和植被遮挡；统一渲染表现不等于将东西花园做成相同外观。
9. **新检查点与 GLB。** 另存正式候选版本和独立 GLB，完成重开、导入和网页检验。校园接入属于后续独立阶段，届时遵循集成技能；不在本轮计划阶段覆盖现有资产。

每阶段通常两批低分辨率诊断和一批最终比较即可。出现实质失败可追加针对性检查，并记录原因；不能一直输出未经验证的“after”图片。

## 6. 版本、反馈与完成定义

- 输出使用独立版本目录，例如 road-rebuild-v1/diagnostic-01、diagnostic-02 和 candidate；不反复覆盖同一个 after 图片让失败图与最终图混淆。
- 每批 manifest 记录模型哈希、生成脚本和配置摘要、相机参数、材质模式、检查结果、是否通过人工视觉审阅。
- 失败批明确标记 rejected，保留供诊断；只有通过相关计算与视觉检查才能标记 geometry-passed。现场真实性仍单独记录为 confirmed/inferred/unknown。
- 最小成功交付是“西出口至主路的连续道路已经通过纯色、网格、剖面和照片对照”，不是“脚本运行结束”。整体完成还需其余路段和景观关系逐项验收。
- 第一次实际执行的单一目标：建立并验收西出口的小范围道路生成样例。此次到计划结束，不开始实施。

## 7. 算法依据

- Shapely / GEOS 负责二维几何运算，三维高度在本方案中另行求解：[Shapely User Manual](https://shapely.readthedocs.io/en/latest/manual.html)。
- 约束三角化保留输入多边形边界，接口要求 Shapely >= 2.1、GEOS >= 3.10：[constrained_delaunay_triangles](https://shapely.readthedocs.io/en/stable/reference/shapely.constrained_delaunay_triangles.html)。
- 并集、差集和缓冲等接口：[Shapely reference](https://shapely.readthedocs.io/en/stable/_reference.html)。

上述库能力只支持方法选择，不构成这份校园模型已经正确的证明。
