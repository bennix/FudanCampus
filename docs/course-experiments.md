# 课程功能补全与实验说明

本轮用户没有头显，明确要求头显视角模拟。模拟与设备会话是两种不同证据，不能混称。

## 网页验收

在 `web` 执行 `npm run dev -- --host 127.0.0.1 --port 5173`，打开终端实际给出的本地地址。

1. 展开左下方“沉浸视角与性能实验”，选择第四教学楼或化学楼。
2. 校园资源加载稳定后点击“开始头显模拟”。眼高1.65米，原地拖动模拟转头；四元数按 `1-exp(-12*dt)` 平滑跟随。点击“视角复位”，Esc或“退出头显模拟”恢复原来的观察相机。
3. “保存视角图”导出带有模拟标记的PNG及相机/环境JSON。画面是当前场景、当前投影的离屏重渲染，未做照片相机标定。
4. 保持视角不动，勾选优化设置后点击“采集20秒并导出”：预热5秒、采样15秒，导出完整帧样本和统计。实验期间不修改窗口、画质、树木与视角；改变窗口或进入后台会使实验取消。
5. 无兼容设备时真实VR按钮不可用，不影响模拟。设备可用时通过用户点击请求 `immersive-vr` / `local-floor` 会话；姿态与双眼投影由WebXR运行时直接驱动，XR不经过桌面限帧和脏帧跳过，也不额外滤波头部姿态。使用浏览器原生会话退出操作。该路径尚无物理头显验证。
6. 可在进入真实XR前点击“结束后保存XR图”，会话开始5秒后取第一眼投影重渲染图，退出后下载。它不是XR合成器/镜片实拍，不包含镜片畸变和时间扭曲。

## 已有优化与本轮贡献

| 项目 | 原有能力 | 本轮工作 |
|---|---|---|
| LOD | 距离、预算、滞回控制及近中远资源 | 暴露加载/层级状态，实验前要求200项就绪且层级稳定，采样冻结LOD |
| 同材质合批 | 化学楼191→31网格、三角形数不变 | 复用已有成果，不再次声称为本轮新算法或精确GPU调用降幅 |
| 视锥裁剪 | Three.js默认按Mesh包围体裁剪 | 增加受控开关，比较实际提交调用与三角形，不按建筑离屏强行删除 |
| 光影精简 | 省电模式、缓存静态阴影、有限阴影分辨率 | 增加同分辨率下缓存阴影/无阴影对照，提供可选关闭阴影 |
| 交互 | 桌面Orbit/室外步行 | 新增头显视角模拟和WebXR会话入口；二者独立标注 |

## 计量口径

自动脚本 `web/experiment-browser.mjs experiment` 通过本地CDP连接端口9226上的独立Edge页面，不访问外部服务。两个站立视点，每种设置三轮；奇偶轮反转设置顺序，每轮预热2秒、采样5秒。网页按钮使用更长的5+15秒。初次完整资源下载及LOD切换不纳入稳定场景实验，因此本实验不评价冷启动性能。

每个JSON记录用户代理、WebGL驱动、绘图缓冲大小、像素比、视点、相机姿态/投影、画质、LOD版本与完整原始帧序列。平均提交帧率=1000/平均帧间隔；P95/P99为帧间隔分位数；JS提交耗时用performance.now围绕renderer.render计时，不是GPU时间。绘制调用/三角形来自renderer.info.render，缓存阴影预热后不持续重算。真实设备帧率与浏览器RAF提交帧率不可等同。

当前无界面Edge报告Microsoft Basic Render Driver，软件渲染环境的FPS仅说明该环境的运行情况。不能由它推断实际GPU或头显60/72/90Hz达标。裁剪减少提交几何的结论也不保证FPS同比例上升。

## 仍需作者处理

- 身份信息、封面最终确认、正式PDF和最终提交压缩包。
- 若教师严格要求实际WebVR头显实证，模拟不能替代；仍需借用设备取得真实会话、转头稳定性与刷新率证据。当前设备路径只实现，未进行物理设备验收。
- 纯人工对照与有效工时：没有历史计时，不可补造节省比例。可另选一个标准窗/门廊开展有计时的同任务对照，并记录熟练度和顺序效应。
- 实测尺寸控制点与照片相机标定、地图出处仍待补；不编造厘米级精度、总体还原率或照片供应商。
- 提示词质量可按历史可核对的具体误读案例定性分析；测试通过率不能当AI代码生成准确率。

本轮未改变建筑GLB、manifest、资源哈希或碰撞数据；功能直接接入现有网页。恢复记录 `prompts_log/2026-11-14-webxr`。
