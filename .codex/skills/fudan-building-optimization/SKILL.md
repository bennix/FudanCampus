# 单体建筑低成本修模

## 目标

把实拍照片转化为对一个指定建筑的“够像”修正：优先细化外轮廓、体块关系、关键屋顶/檐口/入口和大色块。默认不做材质、贴图、灯光、细碎装饰或全景重建。

## 严格的读取边界

- 先确认用户给出的目标建筑名称、对象名、脚本名或文件路径；不确定时只询问目标，不扫描整个工程。
- 只读取目标建筑对应的生成脚本、必要的共享几何/数据依赖，以及用户上传的实拍照片。不要读取其他建筑脚本、整套模型的无关网格或全量渲染结果。
- 如果目标建筑可由独立脚本生成，优先编辑该脚本并重新生成单体；只有在没有独立入口时才检查总装配脚本。
- 输出或验证时只渲染/检查目标建筑的局部视图。不要为了对比而加载、解析或重建其他建筑。
- 修改前先用最小范围的文件搜索定位依赖；避免递归打开大文件、打印完整场景对象列表或把整座校园模型内容带入上下文。

## 默认工作顺序

1. 锁定一个目标建筑和当前生成入口，记录原始文件路径。
2. 从照片提取有限的可执行观察：平面/立面大致比例、层数、屋顶形状、主要进退关系、入口/塔楼等一级特征、墙面与屋顶的大色块。
3. 只修改能显著提升识别度的参数或几何：整体尺度与比例、主楼体块、屋顶/檐口、显著的附属体块、少量关键开口和色块。
4. 使用低复杂度几何（box、plane、简单 extrude/bevel 等）表达形体；除非照片显示它是建筑识别的关键，否则不要增加窗框、栏杆、砖缝、树木或复杂曲面。
5. 对颜色只使用少量稳定的基础材质/漫反射色，按“墙体、屋顶、玻璃/深色开口、重点色”分组；不制作 PBR 材质、贴图、UV 或真实反射。
6. 生成目标建筑并做一次局部快速检查：轮廓是否更接近照片、体块是否穿插异常、颜色分区是否清楚、是否意外影响其他对象。
7. 汇报改动和未处理项，保留下一轮可继续调整的清晰参数；不要主动扩展到第二栋建筑。

## Astra/照片协作提示

给 Astra 的任务应明确限定为：`只处理 [目标建筑]；仅依据已上传照片；只改轮廓、体块比例、屋顶/入口等显著特征和大色块；不做材质、贴图、细节装饰，也不要读取或修改其他建筑。`

照片证据不足时，宁可保持现有几何并标记“不确定”，也不要凭空添加复杂结构。优先采用多张照片共同支持的特征；单张透视照片只能指导相对轮廓，不能据此过度推断背面布局。

## Token 与变更控制

- 每轮只解决一小组高收益问题，避免把“顺便优化”加入任务。
- 不输出大段模型数据、完整脚本或无关日志；只摘要关键参数、变更文件和局部验证结果。
- 保持目标建筑之外的对象、材质和装配关系不变；如必须触碰共享代码，先说明影响范围，并把改动限制为向后兼容的参数或函数。
- 不为追求照片级一致性增加高面数、复杂材质或大量重复对象。此技能的完成标准是“轮廓和色块明显更接近”，不是最终渲染质量。

## 完成检查

在交付前确认：目标建筑确实是本轮唯一编辑对象；关键轮廓和大色块已处理；没有引入材质/贴图工作；修改可由目标入口复现；快速局部检查没有明显穿插、破面或误改其他建筑。
